# UI 原型分析器

## 概述

本技能用于对UI原型设计图和需求文档进行系统性分析，按照标准化模板生成结构化的页面分析Markdown文档。

**输入材料支持**：
- 📷 UI原型设计图（PNG/JPG等图片格式）
- 📄 需求文档（Markdown、TXT、Word、PDF等文本格式）

**分析覆盖四个维度**：
1. 页面基本信息 — 页面名称、业务场景、面向角色
2. UI 元素分析 — 布局区域、表单组件、按钮控件等
3. 字段信息分析 — 字段定义、数据类型、业务规则
4. 业务关联说明 — 交互流程、角色权限、业务约束

**输出**：按独立页面生成结构化的 Markdown 分析文档。

## 分析流程

### 第一步：收集并解析输入材料

**读取需求文档**（如有）：
1. 扫描工作空间，识别可能的需求文档（*.md, *.txt, *.docx, *.pdf）
2. 解析需求文档内容，提取：
   - 业务场景描述
   - 功能模块定义
   - 字段/参数定义
   - 业务规则与约束
   - 角色权限说明
   - 交互流程描述

**识别页面图片**（如有）：
1. 逐一查看用户上传的每张图片，识别页面内容
2. 判断图片之间的关联关系：
   - **同一页面不同状态**：如"待提交"与"已提交"是同一页面的不同操作状态
   - **同一操作流程的不同步骤**：如点击按钮后的弹窗、跳转后的新页面
   - **完全独立的页面**：无直接关联，单独分析
3. 关联的图片合并为同一个分析文档

### 第二步：融合分析

将需求文档中的业务信息与UI图片中的视觉元素进行融合：

1. **业务信息补充UI**：根据需求文档完善业务场景、字段定义、业务规则
2. **UI信息验证业务**：通过图片验证需求文档中的描述，识别遗漏或冲突
3. **缺失信息标注**：对于需求文档中未描述但UI中可见的内容，以及UI中未展示但文档中提到的功能，在分析中进行标注说明

### 第三步：按模板逐页分析

对每个独立页面（或关联页面组），按照以下四个维度进行分析：

1. **页面基本信息** — 页面名称（含状态）、业务场景、面向角色
2. **UI 元素分析** — 列出页面所有可见的UI组件，包括布局区域、列表、表单、按钮、标签页、弹窗等
3. **字段信息分析** — 列出所有表单字段/数据展示字段，标注字段属性
4. **业务关联说明** — 标注业务角色、前后交互关系、业务规则与约束

### 第四步：生成 Markdown 文档

每个独立页面（或关联页面组）生成一个独立的Markdown文件，文件命名规则：`{功能模块}-{页面名称}.md`（如 `健康宣教-宣教任务列表.md`）。

所有生成的文档存放到用户当前工作空间目录下。

## 分析模板

详细的字段级分析模板见 `references/analysis-template.md`，每次分析时严格按照该模板格式输出。

## 关联页面处理规则

- 关联图片合并为同一文档，使用二级标题分隔不同状态/步骤
- 在"业务关联说明"中用箭头符号标注流转关系，例如：`点击"提交结论"按钮 → 页面状态变为"已提交结论"`
- 在文档开头用"关联页面"字段列出同组的其他图片编号

## 输出规范

- 每个Markdown文档使用统一的模板格式
- 字段表格使用标准Markdown表格语法
- 按钮和交互元素使用 `按钮控件` / `链接` 等标准术语描述
- 状态描述使用引号标注，如"进行中"、"待开始"
- 所有分析基于图片中可见的内容，不臆测未展示的信息
