# 测试用例设计指南

## 测试用例模板字段说明

| 字段 | 说明 | 填写要求 |
|------|------|----------|
| 序号 | 测试用例编号 | 从1开始递增 |
| 测试点标题 | 简洁描述测试场景 | 用简洁语言描述，避免技术术语 |
| 所属模块 | 按需求文档的模块划分 | 如"用户中心""订单管理" |
| 二级模块 | 模块的子功能划分 | 更细粒度的功能划分 |
| 前置条件 | 测试执行前系统/用户需满足的状态 | 如"用户已成功注册并登录" |
| 操作步骤 | 用户操作流程 | 每步用换行分隔，用数字编号 |
| 测试数据 | 具体的输入/参数 | 如"长度为5的密码""超出范围的数值" |
| 预期结果 | 系统应呈现的反馈 | 用用户可理解的语言描述 |
| 实际结果 | 测试执行后的实际输出 | 测试后填写 |
| 备注 | 补充说明 | 如"边界值测试""关联需求ID" |
| 版本 | 需求版本号 | 如"V1.0" |
| 是否废止 | 用例是否已废弃 | "是"或"否" |

## 测试用例设计方法

### 1. 等价类划分法
将输入数据分成有效等价类和无效等价类，从每类中选取典型数据进行测试。

**示例**: 密码长度测试
- 有效等价类: 6-20位字符
- 无效等价类: 少于6位、多于20位

### 2. 边界值分析法
测试边界值及其附近的值。

**示例**: 密码长度
- 边界值: 5位（无效）、6位（有效最小）、20位（有效最大）、21位（无效）

### 3. 错误推测法
基于经验和直觉推测可能发生的错误，设计测试用例。

**示例**: 
- 输入特殊字符
- 网络中断后继续操作
- 并发操作同一数据

### 4. 场景法
模拟用户实际使用场景，验证业务流程的正确性。

**示例**: 用户登录流程
1. 正常登录 → 进入首页
2. 密码错误 → 提示错误信息
3. 账户锁定 → 提示账户已被锁定

### 5. 流程分析法
分析业务流程，画出流程图，测试每个分支路径。

## 常见测试点分类

### 功能测试
- 基本功能验证
- 数据正确性验证
- 业务规则验证

### 界面测试
- 布局展示
- 交互元素可用性
- 异常状态显示

### 性能测试
- 响应时间
- 并发处理
- 大数据量处理

### 安全测试
- 权限控制
- 输入校验
- 数据保护

### 兼容性测试
- 不同浏览器/设备
- 不同网络环境
- 数据兼容性

## 必测场景清单

### 增删改查测试
- [ ] 新增功能 - 正常新增、必填校验、唯一性校验
- [ ] 编辑功能 - 正常编辑、边界修改、权限限制
- [ ] 删除功能 - 正常删除、二次确认、关联删除
- [ ] 查询功能 - 精确查询、模糊查询、无结果查询
